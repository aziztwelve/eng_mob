# Проверка облачного онбординга — 18 октября 2026

Реализованы только шесть экранов: приветствие → цель → возраст → уровень → время напоминания → регистрация. Страница входа — выбранный вариант 2. Скриншоты реального Android находятся в `verified/`; сравнения с выбранными изображениями — `design-comparison.jpg` и `login-comparison.jpg`. Итоговая визуальная проверка записана в корневом `design-qa.md`.

## Результаты

- Телефон Redmi 8A, приложение com.aziztwelve.engmob, Metro 8081, серверный API https://api.lingoiq.online/api/v1.
- Переходы по всем шести экранам, запрет продолжения без выбора, возврат и сохранение выбора, старые ссылки, ошибки форм, показ пароля, клавиатура, английская/казахская локализации и прокрутка входа в горизонтальной ориентации проверены. Сценарии запускали реальные React обработчики через Hermes inspector; клавиатура, Back, поворот и прокрутка проверены через ADB, изображения сняты с телефона.
- TypeScript и scoped ESLint прошли. Четыре теста очистки local storage и offline-очереди прошли.
- Go-тесты auth-service, user-service и gateway прошли.
- Миграция 007 из коммита a90af85 развёрнута на сервере. У 2308 существующих профилей (1188 users + 1120 public) старые ответы очищены. Остальных данных профилей тест не изменил. До очистки старые ответы были у 1137/1109 строк; после — 0/0. Защитный триггер удаляет эти ответы при записи из старого клиента. Legacy-колонки сохранены ради совместимости APK.
- Миграция проверена транзакционным тестом с ROLLBACK: повторное применение, старые UPDATE и контроль сохранности остальных данных. Это SQL-only изменение: бинарники Go не менялись.
- Серверный backup перед очисткой: /root/backups/onboarding-six-screens-20261018.sql.gz (доступ root).
- Публичный HTTP smoke: /health → 200, пустые POST /api/v1/auth/login и /register → 400, /api/v1/onboarding без авторизации → 401.

## Как повторить

Из eng_mob:

```sh
node --test scripts/test-onboarding-cleanup.cjs
node --max-old-space-size=1536 node_modules/typescript/bin/tsc --noEmit
git diff --check
```

Из backend:

```sh
python3 scripts/test_six_screen_onboarding.py --ssh root@167.233.103.233
```

На телефоне: Начать учиться → выбрать цель → возраст → уровень → время → регистрация. Вернуться назад и проверить выбор. В регистрации сфокусировать пароль: поле должно оставаться над клавиатурой; элементы ниже доступны прокруткой. Во входе проверить пустую форму, неверный email, короткий пароль и глазик. Старые ссылки paywall/placement-test должны перенаправлять на оставшиеся страницы.

Настоящий вход/регистрация с учётными данными и OAuth не проверялись; аккаунты тестами не создавались. Восстановление пароля сохраняет прежнюю информационную заглушку. Сборка APK/Gradle для этих TypeScript-изменений не запускалась.

## Metro: проверка ограничения памяти

Обнаружено: требуемые рабочим процессом 512 МБ не выдерживают текущий граф из 8038 модулей — после выдачи bundle процесс завершился с `JavaScript heap out of memory`. Для продолжения проверки использован heap 768 МБ и один worker. Это исключение обусловлено воспроизведённым OOM, а не снятием ограничения памяти. Лог попытки 512 МБ: /tmp/metro.log; текущего запуска: /tmp/metro-768.log. Исходный процесс без лимита занимал около 2,3 ГБ RSS. Gradle не запускался.

После запуска с 768 МБ bundle загружен на телефон, страница «С возвращением» отображается (verified/19-login-after-metro-restart.png), Metro /status отвечает running. RSS при проверке: VmHWM:	  924872 kB, VmRSS:	  878432 kB. Холодный debug-запуск после перезапуска bundler занимает заметное время; это не измерение production APK.
